# Phase 1 Landing Page Content System

## Narrative

The public landing page follows this customer-question sequence:

1. **What is Ottimo?** — Hero/value proposition.
2. **Why does this matter?** — Explain why isolated scores and disconnected tools are insufficient.
3. **What does Ottimo inspect?** — Six core domains.
4. **How does it work?** — Discover → Understand → Prioritise → Verify.
5. **What will I actually receive?** — Show the audit/report experience.
6. **Why should I trust it?** — Evidence-first methodology, measured/inferred/unavailable.
7. **What can I do with the findings?** — Actions and verification.
8. **What does Ottimo not claim?** — Limitations and honest boundaries.
9. **What questions will customers have?** — FAQ.
10. **What should I do next?** — Website + email onboarding CTA.

## Content rules

- Plain English first; technical depth second.
- Every claim must be defensible.
- Never imply search rankings, traffic, conversions or AI visibility from technical observations alone.
- Clearly label illustrative/demo content.
- Keep current capabilities distinct from future roadmap capabilities.
- Use the same terminology as the application.
- Prefer evidence and explanation over scores.
- Make the primary CTA consistent with Phase 2 onboarding.

## Six domains

- Performance — speed, responsiveness and observable loading/rendering signals.
- Search visibility — crawlability, metadata, structure and indexability-related signals.
- Accessibility — structure, keyboard interaction, content and automated accessibility signals.
- Experience — navigation, hierarchy, forms, mobile behaviour and interaction friction.
- Technical quality — links, resources, redirects, HTTP/site-integrity signals.
- AI readiness — structured information, page identity and machine-readable context.

## Section contract

### Hero
User question: What is Ottimo?
Purpose: State the value in one sentence and provide the primary onboarding CTA.

### Problem
User question: Why not use isolated tools?
Purpose: Explain that performance, search, accessibility, UX and technical health overlap.

### Coverage
User question: What does Ottimo actually check?
Purpose: Introduce the six domains with concrete examples.

### Method
User question: What happens after I start?
Purpose: Explain Discover → Understand → Prioritise → Verify.

### Audit example
User question: What will the result look like?
Purpose: Show a deterministic, clearly labelled example with evidence and actions.

### Evidence
User question: Why should I trust the result?
Purpose: Explain measured/inferred/unavailable and the refusal to manufacture certainty.

### Action
User question: What do I do with the findings?
Purpose: Show prioritised recommendations and the verification loop.

### Trust/limitations
User question: What can Ottimo not know?
Purpose: Set accurate expectations and explain evidence boundaries.

### FAQ
User question: What practical concerns remain?
Purpose: Address audit scope, public websites, technical depth, evidence, privacy and what happens next.

### CTA
User question: How do I start?
Purpose: Collect website URL and, in Phase 2, email address.

## Responsive/accessibility contract

- One logical heading hierarchy.
- Each section has a meaningful landmark/heading relationship.
- Primary CTA remains obvious at mobile widths.
- No information is communicated by colour alone.
- Illustrative data is textually labelled.
- Keyboard users can reach every interactive element in logical order.
- Focus is visible.
- Decorative icons are hidden from assistive technology.
